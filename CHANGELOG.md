# Changelog

What changed between one tag and the next, not what changed between commits.
This file holds the release that has not been tagged yet;
[the releases page](https://github.com/nevindra/nilo/releases) holds the ones
that have, one page each. What was measured and what was got wrong on the way is
in [`docs/history.md`](./docs/history.md); what is coming is in
[`docs/roadmap.md`](./docs/roadmap.md), and what was refused or answered is in
[`docs/decided.md`](./docs/decided.md).

## Unreleased

### Breaking

- **A raw statement a test reaches may now fail it**, where a column's type is not the one the field reads or an outer join can leave it NULL in a field that is not optional (ADR 233). The message names the column and the fix. A Wire written outside this repository owes `describe(arena, sql, nulls)`, and answering null keeps it unchecked; a Dialect owes `reads`. ([reference](./docs/reference/sql.md#queries), [guide](./docs/guide/sql/raw.md#column-types-checked-the-first-time-it-runs))
- **An upsert's conflict target has to be the key or a declared `.unique`** on a table this program builds, and a unique that ignores case does not count. Both databases refused the others when the statement ran; now they do not compile. Declare the unique in the marker, or `.managed = false` for a table something else builds (ADR 151). ([reference](./docs/reference/sql.md#upserts), [guide](./docs/guide/sql/writing.md#upserts-insert-or-update))
- **`updateReturningOne` refuses a `.where` that could match more than one row.** It has to hold the key, or every column of a `.unique`, with `=`; other terms beside them are fine. It used to update every matching row and hand back the first. `updateReturning` is the call for a condition that means several (ADR 146). ([reference](./docs/reference/sql.md#rawone-updatereturningone-deletereturningone), [guide](./docs/guide/sql/writing.md#returning-the-changed-rows))
- **`generate --drop` names what it drops**: `--drop users.nickname,notes,extension:pgcrypto`. A bare `--drop` names nothing and writes nothing, and the refusal prints the command with the names filled in. `migrations.Options.allow_destructive` is gone, replaced by `.drop`, a list of the same names; `sql.cli.Request.allow_destructive` is `.drop` and `.drop_bare`. A field renamed without `.was` used to be dropped by the same flag as the column somebody meant to drop (ADR 123). ([reference](./docs/reference/sql.md#the-commands), [guide](./docs/guide/sql/migrations.md#dropping-data-needs-a-name))
- **A column type that does not widen is destructive, and has to be named with `--drop table.column`.** `int8` to `int4`, `float8` to `float4`, `numeric(10,2)` to `numeric(10,1)` and `timestamptz` to `timestamp` can refuse, round or reinterpret the rows already there; they were written like any other step. Widenings go through as before (ADR 123). ([reference](./docs/reference/sql.md#the-diff), [guide](./docs/guide/sql/migrations.md#dropping-data-needs-a-name))
- **`migrate.applyPending` refuses to apply anything when a version it already ran was edited**, `error.SchemaDrift`. It used to apply the versions after it on top. It also makes the ledger itself, so the `ensureLedger` call in front of it can go (ADR 123). ([reference](./docs/reference/sql.md#the-ledger-and-applying), [guide](./docs/guide/sql/migrations.md#applying-migrations))
- **On SQLite, a version runs with foreign keys off and checked once before its COMMIT**, through the new `wire.Begin.rebuilding`. The `DROP TABLE` of a table rebuild used to delete the old table's rows first and fire every `ON DELETE CASCADE` pointing at it, inside the version. A version that leaves a row pointing at nothing now answers `error.ForeignKeyViolated` and keeps nothing. A SQLite `.sql` twin carries the same pragmas, so `db check` reports every existing twin stale until the next `db generate` writes them again (ADR 123). ([reference](./docs/reference/sql.md#the-ledger-and-applying), [guide](./docs/guide/sql/migrations.md#applying-migrations))
- **`tx.commit()` on a transaction a failed statement aborted answers `error.QueryFailed` and rolls back**, on both databases. On Postgres it used to report success: the `COMMIT` came back tagged `ROLLBACK` with no error, so a handler that caught a statement's error without a savepoint and then committed answered 200 having kept nothing. SQLite, which keeps a transaction going after a failed statement, is held to the same rule, and every statement after the failure is refused until `sp.rollback()` on a savepoint taken before it. What to change: a statement whose failure a handler means to carry on past gets a savepoint around it (`var sp = try tx.savepoint();`, `sp.rollback()` in the `catch`), or becomes `insertOrIgnore` when the failure it expects is a duplicate (ADR 043, ADR 065). ([reference](./docs/reference/sql.md#errors), [guide](./docs/guide/sql/transactions.md#savepoints))
- **A serialization failure (`40001`) and a deadlock (`40P01`) are `error.RolledBack`**, new in `wire.Error`, where they were `QueryFailed`. It is the one error where running the whole transaction again is right, and a handler that lets it escape answers 503. What to change: a `switch` over `wire.Error` that is exhaustive gains an arm (ADR 117). ([reference](./docs/reference/sql.md#errors), [guide](./docs/guide/sql/transactions.md#retrying-a-rolled-back-transaction))
- **`error.Disconnected` answers 503 when a handler lets it escape**, where it answered 500. What to change: nothing, unless a test pinned the 500 (ADR 117). ([reference](./docs/reference/sql.md#errors), [guide](./docs/guide/sql/running.md#errors))
- **An `update` or a `delete` whose condition matches every row with the values it was handed is refused before it is sent**, as `error.QueryFailed` with a line naming the call. The two ways there are an empty `.not_in` list, `"id" <> ALL('{}')`, which is true of every row, and a pattern built from empty text, `.contains = ""`. A term that narrows beside either is sent as before. What to change: a call that meant every row says so with `db.raw` (ADR 149). ([reference](./docs/reference/sql.md#errors), [guide](./docs/guide/sql/writing.md#update-and-delete-need-a-condition))
- **`rawPage` and `rawPageOrdered` refuse an `OFFSET` nilo cannot set back to 0**: one written as a number other than 0, as arithmetic, or with a placeholder another clause also uses, values handed over as a named struct, and SQLite's `LIMIT a, b`. What to change: write `OFFSET $n` (`$n::int` is fine) and work the number out in Zig. It is what lets a page past its last row say its total (ADR 205). ([reference](./docs/reference/sql.md#queries), [guide](./docs/guide/sql/raw.md#a-paged-join-rawpage))

- **A WebSocket can sit in more than one `Room`**, and `error.AlreadySeated` is gone from `nilo.Room.Error`. Joining a second room used to be refused; it is now a seat in each, drained by the same `receive`, and `leave` gives up one room and keeps the rest. What to change: a `switch` on the error that names `error.AlreadySeated` drops that arm. `Socket.ticket()`, `inRoom()`, `seatedIn()` and `unseat()`, which were public for the Room's use, are replaced by `seating()` and `leaveRooms()`, and `room.Ticket.index` is a `u32` (ADR 035). ([reference](./docs/reference/streaming.md#several-rooms), [guide](./docs/guide/websocket.md#broadcasting-with-niloroom))
- **The session cookie is `__Host-session` wherever the prefix can hold** (`Secure`, `Path=/`, no `Domain`, the defaults), and that name is read before `session`. A sibling subdomain could plant a `session` cookie of its own under a path of this site, and the victim worked inside the attacker's account. Nobody is signed out: a `session` cookie still opens, and the next `set` moves it. What to change: `app.guard(…, "session")` becomes `app.guard(…, nilo.session.host_cookie_name)`, and a test or a client that reads the cookie by name reads the new one. A session with a `domain`, another `path` or `secure = false` keeps the plain name (ADR 033). ([reference](./docs/reference/ctx.md#the-cookie-name), [guide](./docs/guide/sessions.md#the-__host--cookie-name))

### Added

- **`.unread` in the marker: a column the table has and its Row does not read.** `.unread = .{ .created_at = sql.Timestamp }` puts the column in the table, the migration diff and `db.checking`, and lets `.where`, `.order`, `.set` and an insert name it on this Row and every Row that borrows the table, while this Row's `SELECT` list and its JSON leave it out. For the table Row that is also the response (ADR 234). ([reference](./docs/reference/sql.md#a-row), [guide](./docs/guide/sql/tables.md#a-column-the-row-does-not-read))
- **`pub const nilo_through`: a column of another table read flat.** `.customer_name = .{ .customer_id, .name }` joins through the reference and reads `name` into a field of its own, so a response whose contract is flat needs no second struct; `.{ .org_unit_id, .customer_id, .kind }` goes two tables away. Named in `.where` and `.order` like a column, and optional exactly when a reference on the way or the column may be null. `.{ .path = .{ … }, .otherwise = false }` reads `false` where the path does not reach, and `.{ .path = .{ … }, .join = .inner }` leaves that row out of the list and its count (ADR 235). ([reference](./docs/reference/sql.md#nilo_through), [guide](./docs/guide/sql/shapes.md#reading-a-parents-column-as-a-flat-field))
- **`.exists` and `.not_exists` without a `.where`** ask whether any row of the other table points at this one: `.not_exists = .{.{ .in = Deal }}` is "the Org Units no Deal points at". Still refused when the key is this Row's own, and `.where = .{}` is refused in both directions (ADR 218). ([reference](./docs/reference/sql.md#exists-a-condition-on-another-table))
- **`db.raw` reads into a Row with a through field, an aggregate or a count of children**, one column each, filled by position and held against the Row on its first run. A parent or children are still refused (ADR 218, ADR 235). ([reference](./docs/reference/sql.md#which-calls-accept-these-rows), [guide](./docs/guide/sql/shapes.md#what-still-needs-raw))
- **`.now` and `.today` move by a number written out**: `.closed_at = .{ .gte = .{ .today = -90 } }` is `CURRENT_DATE - 90`, and `.seen_at = .{ .gt = .{ .now = .{ .days = -90 } } }` is `now() - interval '90 days'`, with SQLite's `date('now', '-90 days')` and the same modifier on its clock. Nothing is bound, so "the last ninety days" is the database's calendar and not the server's. `.now` names its unit, one of `.days`, `.hours`, `.minutes` and `.seconds`. Both words, moved or not, also stand in an aggregate's or a `nilo_children` entry's `.where` (ADR 181). ([reference](./docs/reference/sql.md#conditions), [guide](./docs/guide/sql/reading.md#conditions))
- **`nilo_children` takes `.max` and `.min`**: `.latest_target = .{ .max = .{ Item, .target_date } }` is the latest `target_date` of the rows pointing back, read by the same correlated subquery a count is, into a `?` of the column's type (ADR 218). ([reference](./docs/reference/sql.md#nilo_children), [guide](./docs/guide/sql/shapes.md#ordering-filtering-and-counting-children))
- **A `nilo_children` entry's `.where` follows a reference**, the way an aggregate's does: `.open = .{ .count = Item, .where = .{ .state_id = .{ .category = .{ .not_in = .{ .done, .cancelled } } } } }` joins the state inside the count's subquery, and a children list's `.where` joins it into the list's statement (ADR 218). ([reference](./docs/reference/sql.md#nilo_children), [guide](./docs/guide/sql/shapes.md#ordering-filtering-and-counting-children))
- **`db.find` takes a key the Row does not carry**, as `db.one` does with the key in `.where`: a Row that carries only a parent is found by its table's key (ADR 218). ([reference](./docs/reference/sql.md#queries))
- **A raw statement is held against its Row the first time it runs.** Each column's type and, on Postgres, whether it comes from the side of an outer join that may find nothing are asked of the database once per statement, and a misfit (`count(*)` into an `i32`, a `LEFT JOIN LATERAL` column into a field that is not optional) fails the statement in a test binary and is a warning in a server. Every call after the first costs one atomic load. `db.raw`, `rawOne`, `rawExactlyOne`, `rawOrdered`, `rawPage` and `rawPageOrdered`; not `tx.raw`, not `db.composed` (ADR 233). ([reference](./docs/reference/sql.md#queries), [guide](./docs/guide/sql/raw.md#column-types-checked-the-first-time-it-runs))
- **`db.deleteReturningOne` and `tx.deleteReturningOne`**: delete the one row the key or a unique pins and answer with it, or null. What taking a one-time token is, since the check and the removal are one statement; the sessions guide's password reset is written with it now (ADR 146). ([reference](./docs/reference/sql.md#rawone-updatereturningone-deletereturningone), [guide](./docs/guide/sql/writing.md#returning-the-changed-rows))
- **`.set = .{ .title = sql.given(body.title) }` is a PATCH in one statement.** It writes `COALESCE($1, "title")`, so a field the body left out keeps what the row holds. Refused on a column that may be NULL, where null is a value somebody may mean (ADR 149). ([reference](./docs/reference/sql.md#options), [guide](./docs/guide/sql/writing.md#a-patch-in-one-statement))
- **`.set = .{ .updated_at = .now }` stamps a `sql.Timestamp` column with the database's clock**, the same expression `.default = .now` writes, with nothing bound. On Postgres it is the transaction's start, so every `.now` inside one `Tx` is one instant (ADR 181). ([reference](./docs/reference/sql.md#options), [guide](./docs/guide/sql/writing.md#a-patch-in-one-statement))
- **`.set = .{ .start_date = .today }` stamps a `sql.Date` column with the database's date**, `CURRENT_DATE`, and `.now` and `.today` stand in a condition too: `.where = .{ .start_date = .{ .gt = .today } }`, nothing bound. Each is refused on the other's column type (ADR 181). ([reference](./docs/reference/sql.md#options), [guide](./docs/guide/sql/reading.md#conditions))
- **`.ieq` and `.not_ieq`: equality that ignores case**, `lower("email") = lower($1)` on Postgres and `COLLATE NOCASE` on both sides on SQLite, the expression a `.unique` with `.ignoring_case` indexes. The lookup the upsert refusal already named, and an `_` in an address is a character rather than `.ilike`'s wildcard (ADR 181). ([reference](./docs/reference/sql.md#conditions), [guide](./docs/guide/sql/reading.md#conditions))
- **`.in` and `.not_in` take `sql.given`.** `.stage = .{ .in = sql.given(q.stages) }` drops the term when the list is null and keeps it when there is one, empty included, so a multi-select on a filter bar is one statement. It was a Refusal that read an absent list as an empty one (ADR 149). ([reference](./docs/reference/sql.md#sqlgiven-a-filter-that-may-be-absent), [guide](./docs/guide/sql/reading.md#optional-filters))
- **`db.rawPageOrdered` and `tx.rawPageOrdered`**: a raw statement read as a page, with the request's `ORDER BY` through `{order}`. A sorted list screen was `rawOrdered` for the rows and a second statement for the total with the `WHERE` pasted in again (ADR 205). ([reference](./docs/reference/sql.md#dbrawordered-and-dbrawpageordered), [guide](./docs/guide/sql/raw.md#a-paged-join-rawpage))
- **`.order` on a narrower Row may name a column of its table the Row does not carry**, a tiebreak the response has no reason to show. On a grouped Row it is a Refusal (ADR 218). ([reference](./docs/reference/sql.md#options), [guide](./docs/guide/sql/reading.md#sorting-chosen-by-the-request))
- **An aggregate may carry a `.where`**: `.idr = .{ .sum = .amount_minor, .where = .{ .currency = "IDR" } }` is `sum(…) FILTER (WHERE …)` on both databases, with the values written in. A filtered `sum`, `min`, `max` or `avg` is optional whatever its column; count matching rows with `.{ .count = .id, .where = … }`. A column with a `.references` is a way into the row it points at, `.where = .{ .state_id = .{ .category = .done } }`, joined once (ADR 218). ([reference](./docs/reference/sql.md#nilo_aggregate), [guide](./docs/guide/sql/shapes.md#filtering-one-aggregate))
- **`pub const nilo_children`: an order and a condition for a children field, and a count of children.** `.lines = .{ .order = .{ .position = .asc }, .where = … }` orders and narrows the second statement; `.line_count = .{ .count = Line }` is an `i64` field read by a correlated `count(*)` in the same statement, sortable and usable in `.where`, with no child read (ADR 218). ([reference](./docs/reference/sql.md#nilo_children), [guide](./docs/guide/sql/shapes.md#ordering-filtering-and-counting-children))
- **`sql.Sent.route`**: the `operationId` of the route whose request sent the statement, read off the Scope, null under a `Run`. A watcher can say which page a slow statement belongs to (ADR 108). ([reference](./docs/reference/sql.md#dbwatching-and-sqlsent), [guide](./docs/guide/sql/running.md#logging-statements-dbwatching))
- **`db.rawExplain(c, sql, values)` and `db.rawExplainOrdered(c, sql, values, order)`**: `db.explain` for a statement nilo did not write, inside a transaction that is rolled back, since `ANALYZE` runs what it plans (ADR 232). ([reference](./docs/reference/sql.md#dbexplain), [guide](./docs/guide/sql/running.md#query-plans-dbexplain))
- **`.where` on a narrower Row may name a column of its table the Row does not carry**, as `.order` already could, bound as the table's column type (ADR 218). ([reference](./docs/reference/sql.md#options), [guide](./docs/guide/sql/reading.md#sorting-chosen-by-the-request))
- **`.today` on `sql.AsText("date")` and `.now` on `sql.AsText("timestamptz")`**, in a `.set` and in a condition: the database writes the value either way. On SQLite `.now` there is RFC 3339 text rather than microseconds (ADR 181). ([reference](./docs/reference/sql.md#options), [guide](./docs/guide/sql/reading.md#conditions))
- **`db.explain(Row, c, options)`**: the plan of the statement `db.select` would send with the same values, `EXPLAIN (ANALYZE, BUFFERS)` on Postgres and `EXPLAIN QUERY PLAN` on SQLite, for a test to hold a plan to what it should be (ADR 232). ([reference](./docs/reference/sql.md#dbexplain), [guide](./docs/guide/sql/running.md#query-plans-dbexplain))
- **`routeNameOf(scope)`** in `nilo_core`, beside `requestIdOf`: a Scope's route name, or null for one without a `routeName` (ADR 108).
- **`tx.composedOne`**, the one row of a composed statement inside a transaction, as `db.composedOne` is outside one (ADR 208). ([reference](./docs/reference/sql.md#tx), [guide](./docs/guide/sql/raw.md#building-a-statement-at-run-time-sqlcomposed))
- **`sql.violated(c, Row, .{ .email })`**: whether the last statement broke the key or the `.unique` over those columns, checked against the marker while compiling. It accepts Postgres's constraint name and SQLite's column list alike, so a handler branching on which unique fired answers the same on both (ADR 117). ([reference](./docs/reference/sql.md#sqlviolated), [guide](./docs/guide/sql/running.md#which-constraint-failed-sqlproblem-sqlviolated))

- **`c.eventsFrom(rooms, .{})` is an event stream fed by Rooms, handed to the connection rather than kept by its handler.** Every post said into the rooms goes out as an event, a comment keeps a quiet connection speaking every 30 seconds, and the stream ends when the client goes or the server stops. It costs 5,184 bytes a connection, an idle connection's figure, where a stream a handler holds costs 21,566. One Room can hold WebSockets and event streams together; a binary post is counted as missed for a stream rather than sent (ADR 227). ([reference](./docs/reference/streaming.md#an-event-stream-fed-by-rooms), [guide](./docs/guide/streaming.md#event-streams-fed-by-a-room))
- **`room.event(.{ .name, .id, .data })` says one event with a name or an id.** An event stream sends all three; a WebSocket gets `data` as a text message. A line break in `name` or `id` is `error.EventFieldBreaksLine`, new in `nilo.Room.Error` (ADR 227). ([reference](./docs/reference/streaming.md#room), [guide](./docs/guide/streaming.md#event-streams-fed-by-a-room))
- **`nilo.Rooms` lends a Room to a key the application makes up**, from a pool sized at `init`: every tab a user has open joins `"user:42"`, and `rooms.json("user:42", …)` from anywhere reaches all of them. A key nobody is under costs nothing to say into, the last one out gives the Room back, and when every Room is lent a new key is `error.NoRoomFree`, a 503 in `eventsFrom`. `c.eventsFrom` takes `rooms.named(key)` beside or instead of a Room (ADR 228). ([reference](./docs/reference/streaming.md#rooms), [guide](./docs/guide/websocket.md#reaching-one-user-on-every-tab-nilorooms))
- **A Room made with `.history` catches a returning event stream up.** It keeps its latest text posts, bounded by count and by `history_bytes` (64 KiB), and `c.eventsFrom` writes the ones after the client's `Last-Event-ID` before anything new. Give every post in such a Room an id with `room.event` (ADR 229). ([reference](./docs/reference/streaming.md#a-client-that-comes-back), [guide](./docs/guide/streaming.md#event-streams-fed-by-a-room))
- **`nilo.blockingReserved(f, args)` is `nilo.blocking` on a thread of its own**, rather than a place in the pool's queue behind a call already running. For a call made while holding a connection or a lock; every call that finds no idle worker starts one, so it is for callers that are already bounded (ADR 064). ([reference](./docs/reference/app.md#concurrency))

### Changed

- **A gRPC call runs on its connection's thread** rather than the next one round-robin, which sent nearly every call to another thread and its answer back: 2.7x the unary calls a second at 256 connections, and the worst call at 52 ms rather than 1.5 s (ADR 220).
- **zio is pinned at `0299e57` on its `main`**, for `spawnInto` and the fix below, and built with its tasks pinned to the thread they start on through zio's own build option (ADR 199). Nothing to change in an application. One that also depends on zio itself passes `.scheduling = .pinned` to its own `b.dependency("zio", …)` as well, or it builds a second, differently configured zio beside nilo's. A stripped binary is 6.9 KB larger (ADR 017).
- **A cached Postgres statement takes one round trip rather than two.** pg.zig is pinned at `nevindra/pg.zig@0a8dab4`, lalinsky's `ec8cf27` plus two fixes from karlseguin's `master`: a cached statement no longer sends a `Sync` of its own and waits before Bind and Execute, 2.1–3.1 µs off every query over a unix socket and about three times that through a Docker port; and `startup_parameters` now reach the server. Nothing to change in an application. The pin moves back to lalinsky's once lalinsky/pg.zig#13 merges ([`sql.md` §16](bench/result/sql.md#16-the-round-trip-pgzig-wasted-taken-back)). ([reference](./docs/reference/sql.md#prepared-statements), [guide](./docs/guide/sql/running.md#prepared-statements))

### Fixed

- **An aggregate's `.where` takes a value of the column's own enum**, so `.not_in = &finished` with `finished` a `[_]Category` reads as `.not_in = .{ .done, .cancelled }` does. It was refused with a message about a string nobody wrote; a value of another enum is still refused, now with a message that says how the words are written (ADR 218). ([reference](./docs/reference/sql.md#nilo_aggregate), [guide](./docs/guide/sql/shapes.md#filtering-one-aggregate))
- **A page past its last row answers its real total**, where it answered 0: `db.page` and `tx.page` send one `db.count` with the page's `.where` when a page that skipped rows comes back empty, and `rawPage` and `rawPageOrdered` ask the same statement again from its first row (ADR 150, ADR 205). ([reference](./docs/reference/sql.md#dbpage), [guide](./docs/guide/sql/reading.md#paging-with-a-total))
- **An order term that says where NULLs go compiles on a shaped Row**, through a parent and on an aggregate; it failed inside `shape.zig` (ADR 218). ([reference](./docs/reference/sql.md#a-parent-children-a-group), [guide](./docs/guide/sql/shapes.md#joining-a-parent-row))
- **A statement whose prepared plan a migration made stale runs, rather than failing on every connection until the pool replaces it.** A column's type changed under a running server made Postgres refuse each kept plan with `0A000`. Outside a transaction the plan is deallocated and the statement sent again; inside one the answer is `error.RolledBack` and the next attempt prepares it fresh (ADR 051). ([reference](./docs/reference/sql.md#prepared-statements), [guide](./docs/guide/sql/transactions.md#retrying-a-rolled-back-transaction))
- **A `COMMIT` is not cut off by a cancellation**, so its outcome is always known: it used to be able to answer `QueryFailed` for a transaction that had landed (ADR 223). ([guide](./docs/guide/sql/transactions.md#giving-a-statement-a-deadline))
- **A statement sent into an aborted Postgres transaction is answered `25P02` instead of destroying the connection**, and costs no reconnect (ADR 043). ([reference](./docs/reference/sql.md#errors), [guide](./docs/guide/sql/transactions.md#savepoints))
- **A SQLite `COMMIT` the database refused, a deferred foreign key or a `BUSY`, no longer returns the writer to the pool with the transaction still open** (ADR 065). ([reference](./docs/reference/sql.md#tx), [guide](./docs/guide/sql/sqlite.md#one-writer-several-readers))
- **`.where = .{ .deleted_at = null }` on an `update` or a `delete` compiles.** A condition that binds no parameter was refused as though it were no condition (ADR 149). ([reference](./docs/reference/sql.md#null-in-a-condition), [guide](./docs/guide/sql/writing.md#update-and-delete-need-a-condition))
- **A statement the database refused logs at `warn`, not `err`**, on both Wires: it is a request failing, and `err` says the server is refusing to start.
- **A plan that drops an indexed column runs on Postgres.** The column went first and took its index with it, and the `DROP INDEX` after it failed the whole version; indexes that are going now go before the columns (ADR 123). ([reference](./docs/reference/sql.md#the-diff), [guide](./docs/guide/sql/migrations.md#changing-tables-the-diff))
- **Two processes making the migration ledger at the same moment no longer fail one of them**: `ensureLedger` takes the advisory lock `apply` takes (ADR 123). ([reference](./docs/reference/sql.md#the-ledger-and-applying), [guide](./docs/guide/sql/migrations.md#applying-migrations))
- **On SQLite, an `INSERT … RETURNING` that breaks a constraint reports what SQLite said**, to the watcher and to `sql.problem`. SQLite reports it at the first step, and only the send was asked. `Problem.constraint` is filled on SQLite too, from the text after `constraint failed:` (ADR 117). ([reference](./docs/reference/sql.md#sqlproblem), [guide](./docs/guide/sql/running.md#which-constraint-failed-sqlproblem-sqlviolated))
- **A step that needs a backfill says the fix for its kind.** For an added required column it said to put a data step in front, which cannot fill a column that does not exist yet; it now says to give the field a `.default` or ship it optional first. ([reference](./docs/reference/sql.md#the-diff), [guide](./docs/guide/sql/migrations.md#adding-new-columns-addmissingcolumns))

- **Under `.{ .hop = nilo }`, one slow SQLite read no longer makes every write time out.** A statement queued on the thread pool behind the slow one while holding its connection, and the next write waited on it. Every statement now gets a worker of its own through `nilo.blockingReserved`, bounded by the Gate already in front of the connections ([zio#745](https://github.com/lalinsky/zio/issues/745), ADR 064). ([reference](./docs/reference/sql.md#threading), [guide](./docs/guide/sql/sqlite.md#choosing-threading))
- **An error returned from `main` in a Debug build exits with its trace**, where it printed `panic: cast causes pointer to be null` and hung, and a panic keeps its stack trace rather than ending in `aborting due to recursive panic`. Both came from zio v0.18.0 under `std_options_debug_io = nilo.debug_io` ([zio#744](https://github.com/lalinsky/zio/issues/744)). ([reference](./docs/reference/README.md#declarations-in-the-root-file), [guide](./docs/guide/getting-started.md#logging-setup-std_options-and-debug_io))
- **A container's CPU quota sets the thread count.** With `threads` left at 0 nilo started one executor per core the host has, which a `docker --cpus`, Kubernetes or systemd quota does not hide, and the quota throttled them: on two CPUs of an eight-core machine, a p99.9 of 71 ms. The count is now the quota rounded up plus one, read from the tightest cgroup limit above the process, and startup says so when it is below the cores. At two CPUs that is 22% more throughput and a p99.9 of 10 ms; at four, 4% more and 0.5 ms; with no quota nothing changes. A `threads` past 64, or a machine with more cores than that, is held to 64 where the engine used to assert (ADR 230). ([reference](./docs/reference/app.md#listen-options), [guide](./docs/guide/deploying.md#tuning))

- **`host()` and `scheme()` believe `X-Forwarded-Host` and `X-Forwarded-Proto` only from a trusted proxy**, by the rule `clientIp()` uses: named in `trusted_proxies`, or counted by `trusted_hops` when none is named. They read `trusted_hops` alone, so an app that named its proxies got `scheme() == "http"` behind TLS, and one that set a hop count to fix that believed a forwarded host from any peer, the reset-link poisoning ADR 090 is there to stop. `scheme()` is `"https"` on a listener with its own TLS (ADR 102). ([reference](./docs/reference/ctx.md#chost-and-cscheme), [guide](./docs/guide/deploying.md#client-ip-address-behind-a-proxy))
- **More than eight `X-Forwarded-For` fields no longer makes `clientIp()` answer with the proxy's address.** The last eight fields are read, which are the proxies' end of the list; a client that stuffed the head was read as the proxy, inside an allow-list of private addresses (ADR 102). ([reference](./docs/reference/ctx.md#reading), [guide](./docs/guide/deploying.md#client-ip-address-behind-a-proxy))
- **A control byte anywhere in a request head, a CR that does not end its line, and a method or header name that is not a token are a 400.** `Host: a\r, Upgrade` was one header to nilo and two to a front end that ends a line at the CR, and `Con,nection` a name a front end may split into one it reads. llhttp, Node's parser, refused every one of them; `zig build fuzz-llhttp -Dllhttp` found them (ADR 070, ADR 231). A hand-written client sending such bytes now gets a 400; no browser or HTTP library does. ([design](./docs/design/http1-protocol.md#rules))
- **A request-target in none of RFC 9112's four forms is a 400**, and so are an `http` authority a host cannot be spelled as (`http://|/y`) and `http:` with no `//`. `h;tp://x/y` used to be routed as a path (ADR 095). ([design](./docs/design/http1-protocol.md#rules))
- **`Connection` is read as a list, and `close` anywhere in it closes.** `keep-alive, close` kept an HTTP/1.1 connection open, and `keep-alive, Upgrade` closed an HTTP/1.0 one (ADR 073). ([design](./docs/design/http1-protocol.md#rules))
- **A chunk line ends at CRLF and nowhere else, a chunk extension may not carry a control byte, and a folded header line is a 400.** Each let nilo and a front end frame one request two ways, the TERM.EXT desync among them (ADR 070). ([design](./docs/design/http1-protocol.md#rules))
- **Three waits on a client that claimed a whole bound now have one.** The linger after a refused request is one second in all, not one second per read, which let a byte every 900 ms hold a fiber for eighteen hours (ADR 195). The body a handler never read is thrown away under `body()`'s rate floor, not a per-read limit, and a trailer section stops at 8 KiB (ADR 022). A WebSocket client that stops half way through a frame is closed after twice `idle_ms`, where it was never pinged and held its fiber for ever (ADR 021). ([guide](./docs/guide/deploying.md#what-happens-at-each-limit))
- **A box left blank on an optional or defaulted field is the field not given.** A browser sends an empty box as `age=`, and `Form(T)`, `Query(T)` and both `Bound` forms answered a 400 saying an optional age has to be a whole number. An empty `?Str` is still `""`, and a required field left blank is still refused (ADR 132). ([reference](./docs/reference/handlers.md#formt), [guide](./docs/guide/forms.md#checkbox-groups-and-multiple-selects))
- **`c.upgrade(loop, c)` is refused while compiling**, and so is a `*Ctx` anywhere in the loop's state. The Ctx is gone by the time the loop runs, so the loop read the next request's memory (ADR 062). ([reference](./docs/reference/ctx.md#answering), [guide](./docs/guide/websocket.md#passing-state-into-the-loop))
