# A request body can be sent gzipped, and a chunked body is a function of its own

**Status:** accepted
**Topic:** [fetch](../design/fetch.md)
**Applies:** [ADR 017](./017-the-trade-budget-has-four-axes.md) (a program that never compresses pays nothing), [ADR 062](./062-where-a-connection-waits-is-what-it-costs.md) (a fiber holds its stack at its high-water mark), [ADR 057](./057-percent-is-needed-by-two-layers.md) (a file earns its place in core by being needed by two layers)
**Extends:** [ADR 174](./174-the-body-decides-not-the-method.md) (the length of a streamed body is still mandatory; an unknown one has a function of its own), [ADR 211](./211-a-response-is-compressed-on-a-compressor-borrowed-from-a-pool.md) (the in-place start of the compressor moves to core, the pool is unchanged)

## Context

Two nilo programs talking over a WAN send every byte uncompressed. An agent posts its host's whole inventory as JSON on every turn and OTLP batches of up to a megabyte, and holds a long upload open on which it writes one NDJSON line at a time. `nilo_fetch` could do none of it: `Body` is `none | slice | stream{reader, len}`, `stream` needs a length (S3 and its kind answer `411` to a chunked body), and the caller wrote the chunked upload through `std.http.Client` directly. The server half of the same report (reading zstd, `bodyStream` decoding) and zstd in either direction are not this decision: gzip is what every receiver reads, and the API below is shaped so a second coding is a second constant, not a new API.

## Decision

**A call names the coding it wants its body sent under: `Call.encoding = fetch.gzip`**, or `fetch.gzip.with(.{ .level = .fastest, .min_bytes = 512 })`. For a slice body the compressed bytes go into the Scope's memory, `Content-Length` is their size and `Content-Encoding: gzip` goes out. A body under `min_bytes` (1 KB), one that does not shrink, and one whose headers already name a `content-encoding` go out as they are. `Response.sent_encoding` says which happened.

**A `Coding` is a value, and naming it is what links the compressor.** `fetch.gzip` is a constant whose vtable points at the compressor's functions; a program that never writes it never analyses them. Measured: a program that dials out and never compresses grows by 672 bytes, and one that names `fetch.gzip` by 61,632 more (`bench/result/fetch.md`). A runtime enum switched on inside `send` would have linked `std.compress.flate`'s compressor into every program that dials out, the complaint ADR 017 made of a setting that costs a branch whether anybody chose it. A coding is `name`, `level`, `min_bytes` and four functions (squeeze a slice, open a stream onto a sink, its writer, finish); the call in `fetch.zig` names no codec.

**The compressor is never initialised on a stack.** `Compress.init` builds a 96 KB temporary (99,048 bytes of stack, ADR 211) and a call made from a handler runs on the connection's fiber, which keeps its stack at the high-water mark for the life of the connection (ADR 062). The in-place start that `http/compress.zig` already had (`reset`, field by field into memory that is there, 40 bytes of stack) moves to **`core.deflate`**, because the client needs it too and a Fitting cannot import `nilo_http` (ADR 057). Its one dependency on a private thing, the writer's vtable, is read from a compressor built at compile time, where the temporary is the compiler's: no early call on a big stack, and no run-time `Compress.init` anywhere. `http/compress.zig` now calls the same function; its behaviour and tests are identical, and the libdeflate backend is untouched. The compressor itself (`~288 KB`) lives on the heap in a **stash of one on the `Client`**: the first compressed call allocates it, later ones take it back by a swap on a pointer and reset it, a second call at the same time allocates its own and frees it. A client that never compresses holds one null pointer. A test runs the compressing path on a 48 KB thread stack, where the standard library's own `init` aborts (`encode.zig`).

**A slice is compressed whole; a `Body.stream` is not compressed at all.** Its plain length is known and its compressed length is not, and the two ways out are both worse than sending it as it is: compressing into a buffer first puts the whole body in memory, which is the thing `stream` exists to avoid, and sending it chunked is the 411. A caller with a large body to compress wants the next decision.

**A chunked body is `Exchange.beginUpload`, a function and a type of its own, never an omitted length.** `Body.stream` keeps its mandatory length for the reason in ADR 174: I-do-not-know-it stays a compile error rather than somebody else's 411. `beginUpload(client, c, &up, opts, coding)` sends the head with `transfer-encoding: chunked` (and the `content-encoding`), and `up.writer()` takes the body a piece at a time; `up.end()` finishes the coding, ends the body and reads the head of the answer, after which `ex.take` and the other readers carry on. **`flush` on the writer is the unit**: under a coding it is deflate's sync flush (the bytes so far end on a byte boundary and a reader can decode up to there), then the chunk is ended and written to the socket. std ends a chunk with its `\r\n` only when the next write begins, so `flush` writes that itself: without it the last line sits one trailer short of whole, which a peer that frames by chunk reads as not yet arrived (found by the test that failed on it). The upload is sent on a connection no pool held, as a `.stream` is, and is bounded as a whole by `timeout_ms`, so an open-ended upload says `0`; a redirect is handed back, never followed. Documented, not hidden: some servers refuse a chunked body.

**A 415 is answered once, plain, and not remembered.** A server that does not read the coding answers 415 naming the codings it reads in `Accept-Encoding` (`http/serve.zig`). When the answer lists the coding we used it is about something else and is the answer; when it does not (nilo's own, naming `identity`, or a third party's with no header at all), a slice body is sent again without the coding, once. A streamed upload cannot be replayed and is not retried; the caller sees the 415. The answer is **not** remembered per origin: that is memory and a lock on the `Client`, a stale entry after a server upgrade, and a rule about somebody else's service that nilo cannot check. It costs one extra round trip per call to a server that cannot read gzip, and `Response.sent_encoding == null` after asking tells the caller to stop asking, which is a decision for the caller who knows the server.

**`fetch.testing.Canned` receives it**: `requestEncoding()`, `requestBodyDecoded(gpa)` (the body with its coding undone, for the assertion) beside `requestBody()` (raw), and `serveUpload` (a chunked body read chunk by chunk, each on `uploadSeen()` and counted in `chunks_seen` the moment it arrives).

## Against ADR 017's four axes

- **Allocations per request:** none for a call that names no coding. A compressed call: the output in the Scope (one arena allocation, sized at half the body and grown in place if needed), one for the headers with `content-encoding` added, and on the first one the compressor (`~288 KB`, once per Client).
- **Memory per idle connection:** nothing. The stash is per Client, not per connection, and the compressor is never on a fiber's stack.
- **Throughput and p99:** deflate runs on the calling thread and holds it for the body's length; the numbers are in `bench/result/fetch.md`. A caller chooses its level, and an agent on a busy host chooses `.fastest`.
- **Binary size:** 672 bytes for a program that never names `fetch.gzip`, 61,632 more for one that does (measured).

## What was rejected

**`Call.encoding` as a runtime enum.** Links the compressor into every program that dials out. **Remembering a 415 per origin.** Above. **Compressing a `Body.stream` into a buffer, or chunked.** Above. **A chunked variant of `Body.stream` with an optional length.** It makes the omitted number the way to ask for the 411. **Keeping the in-place start in `http/`.** The client could not reach it. **Initialising one compressor early on a big stack to copy its vtable from.** A comptime-built one needs no stack at all and no ordering.
