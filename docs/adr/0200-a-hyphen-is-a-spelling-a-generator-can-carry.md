# A hyphen is a spelling a generator can carry

[ADR 0149](0149-a-route-can-say-its-own-name.md) lets a route say its own
`operationId`, and checks the name while compiling: letters, digits and `_`,
starting with a letter or `_`. The reasoning was the right one — it is a word
a client generator turns into a method, and the refusal says so rather than
letting the generator find out.

The port that asked for `named` then hit the check on five names it did not
choose:

```
error: nilo: the route name "auth-login" is not something a client generator can turn into a method.
  An operationId is letters, digits and `_`, starting with a letter or `_`: `addPartnerCapability`, not "auth-login".
```

Go's document, generated by huma from what the handlers register, has
`auth-login`, `auth-callback`, `auth-session`, `auth-logout` and
`auth-dev-login`. The other 262 are camelCase because that is huma's default and
nobody spelled those five. A hyphen is legal in OpenAPI, and the TypeScript
client generated from that document carries the five as string keys without
complaint.

## Why the character class moves

**The document on the other side of a port is the contract, and it was spelled
by a generator this framework does not control.** The port renamed the five to
`authLogin` … `authDevLogin` on the Zig side and wrote a test that folds a
hyphen into camelCase and asserts that *exactly five* names differ — so that the
fold could not quietly become a general rewriter. That is a mechanical
difference between two documents describing one API, kept honest by a test,
which is a cost paid for a refusal that was protecting nothing: every generator
in use folds `auth-login` to `authLogin` on its own.

The refusal's own reasoning decides it. An `operationId` has to be "the name the
generated client and your own authorisation table will use". A hyphenated name
*is* that — the generated client already uses it, and the table is keyed by the
string. What the check exists to stop is a name no convention can carry: a
space, a dot, a slash, a leading digit. Those are still refused, and the
Refusal file (`add partner-capability`, with a space in it) still fires.

## What was not done

**A second spelling on the registration** — a marker that carries the published
name while the Zig-side name stays a word — was the port's second preference.
It is one more thing to keep in step for the sake of not typing a hyphen, and
it would put an annotation on a route, which is the one thing
[ADR 0149](0149-a-route-can-say-its-own-name.md) says a route does not carry.

**Rewriting the name** — folding `auth-login` to `authLogin` for the document —
would have made the document disagree with what `named` said, silently. The
whole point of `named` is that the document prints what the route said.

## Against ADR 0018's four axes

Nothing. The check is comptime; a name reaches the document and the route
table as a slice of read-only memory, as it did.

## Consequences

- `named("auth-login")` compiles, and the document and `Ctx.routeName`
  ([ADR 0201](0201-a-middleware-can-learn-which-route-it-is-in-front-of.md))
  both carry it with the hyphen.
- A leading hyphen is still refused: the first character has to be a letter or
  `_`, as before.
- `checkName`'s message names both spellings now — `addPartnerCapability` or
  `auth-login` — so somebody who reads it learns the hyphen is allowed rather
  than working it out from the character class.
