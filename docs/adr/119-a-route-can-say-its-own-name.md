# A route can say its own name

**Status:** accepted
**Topic:** [routing](../design/routing.md)

## Context

nilo writes an `operationId` from the method and the path, at one site, with nothing to override it:

```
putApiPartnersIdCapabilitiesCapability
```

A caller's own name for the same endpoint is `addPartnerCapability`.

That is a good default and it was the only option. The gap turned up where it matters: a caller's authorisation model is a default-deny table keyed by `operationId`, 267 entries, an operation missing from it is refused for everybody, and a test reads the OpenAPI document in both directions to keep the two honest. Under a derived name the keys stop being words anybody chose, and a route that moves path silently changes its key.

It fails shut, which is the right direction. It is still a table nobody can read.

A derived name is bad at the two things a key needs. **It is not a word anybody chose**: a generated client's method is `putApiPartnersIdCapabilitiesCapability`, and so is the row in the caller's table, readable only in the sense that a machine can read it. **It moves when the path moves**: mounting `/api/partners` under `/api/v2` rewrites 30 keys, silently on the caller's side and loud on nobody's, so every moved operation is missing from the table and refused for everybody, correct and not what anybody meant to deploy.

The same table then hit the derived name's replacement on five entries it did not choose: a document generated by another team's tooling had `auth-login`, `auth-callback`, `auth-session`, `auth-logout` and `auth-dev-login`, and the other 262 were camelCase because that was the generator's default and nobody had spelled those five by hand.

## Decision

**A route may say its own `operationId` with `named`, checked while compiling: letters, digits, `_` and `-`, starting with a letter or `_`.**

### The shape

```zig
try app.named("addPartnerCapability")
    .put("/api/partners/:id/capabilities/:capability", addCapability);

const api = app.group("/api");
try api.named("listPartners").get("/partners", listPartners);
```

`named` is the vocabulary `with` and `without` already use ([ADR 099](./099-a-route-can-say-what-covers-it.md), [ADR 008](./008-middleware-is-an-onion-of-ctx-functions.md)): it hands back a group, and which name a route carries is settled while compiling. `GroupOf(prefix, excluded)` became `GroupWith(prefix, excluded, attached)` when `with` landed, and is now `GroupWith(prefix, excluded, attached, name)`, so nothing that named the old type broke, exactly as it did not the last time.

Two routes with the same name stop the process at registration, the way a duplicate route does. The document would carry the same key twice, and whichever consumer read it would see one of the two. A route that says nothing keeps the derived name it always had, and the derivation is untouched.

### The character class includes a hyphen, because the contract is spelled by someone else's tool

`checkName` (`http/app.zig`) checks a name a byte at a time: letters, digits, `_` and `-`, starting with a letter or `_`. A hyphen is admitted because the document on the other side of a port may already have one: OpenAPI permits it, the TypeScript client generated from `auth-login` carries it as a string key without complaint, and every generator in use folds it to `authLogin` on its own. **The document on the other side of a port is the contract, and it was spelled by a generator this framework does not control.** The refusal's own reasoning decides it: an `operationId` has to be the name the generated client and the caller's own authorisation table will use, and a hyphenated name already is that.

A space, a dot, a slash or a leading digit is still refused: those are not a name under any convention, and the Refusal file (`add partner-capability`, with a space in it) still fires. `checkName`'s message names both spellings, `addPartnerCapability` or `auth-login`, so somebody who reads it learns the hyphen is allowed rather than working it out from the character class.

### What this is not

It is not `huma.Operation` coming back. Reading the signature is the whole point of the library ([ADR 016](./016-the-api-description-comes-from-the-signatures.md)), and this changes nothing about what the document says: the parameters, the body, the response and the failure still come from the argument list and the return type. A name is not a description. It is what the endpoint is called, and that is a line worth being able to state: a route may say what it is called and may not say what it does. Anything on the second side of it is an annotation, which is the one thing this framework does not ask for.

## What was rejected

**A trailing options struct on each verb**, `app.get(pattern, handler, .{ .name = "listPartners" })`. One place to look and no new type, at the cost of fourteen changed signatures across `App` and `Group`, and an options struct with one field in it that would attract a second: `.summary`, `.tags` and `.deprecated` all fit in a struct like that and none of them fit the framework, and a shape that makes the wrong thing easy to add is a shape that gets it added. `named` cannot grow that way; it takes a name because it is called `named`.

**A second spelling kept on the registration**, a marker carrying the published name while the Zig-side name stays a word, so a hyphenated document name would never have to touch `named`'s own check. Rejected as one more thing to keep in step for the sake of not typing a hyphen, and as an annotation on a route, which is the line "What this is not" already draws.

**Rewriting the name**, folding `auth-login` to `authLogin` for the document instead of widening the character class. Rejected because it would make the document disagree with what `named` said, silently: the whole point of `named` is that the document prints what the route said. The port's own workaround while the check was still narrow, renaming the five routes to `authLogin` … `authDevLogin` on the Zig side with a test folding a hyphen into camelCase and asserting that exactly five names differ, is the mechanical cost that widening the check removes: every generator in use already folds the hyphen on its own, so the check was protecting nothing.

## What it costs

| Axis | Cost |
|---|---|
| Allocations per request | 0 |
| Memory per idle connection | 0 |
| Throughput and p99 | 0. The name is comptime and reaches the document and the route table (`Ctx.routeName`, [ADR 162](./162-a-middleware-can-learn-which-route-it-is-in-front-of.md)) as a slice of read-only memory, the way the pattern already does. |
| Binary size | 0. One comptime parameter on `GroupWith`, one method on `App` and one on the group, one refusal, one field on `Operation`. |
